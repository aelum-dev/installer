## [Unreleased]

### Fixed
- **Black Wails window / detached devtools on Linux** — export `WEBKIT_DISABLE_DMABUF_RENDERER=1` at the top of `run.sh` (and `build.sh`) to disable WebKit's DMABUF/GPU renderer, which fails to create KMS/GBM buffers on this host and renders the main window and the detached devtools inspector black (Wails issue #2977). `./run.sh` (`wails dev`) now sets it automatically.

### Added
- **Manual partition page auto-scrolls to the FREE row when the add-control reveals** — clicking the clickable "Free" row in the manual partition editor (`frontend/src/pages/ManualPartitionPage.svelte`) now also scrolls the scrollable partition table to its bottom so that row stays visible at the base instead of being pushed out of view by the newly shown add-new-partition control. Implemented with `bind:this={editorEl}` on the `.partition-editor` div and a `$effect` that sets `editorEl.scrollTop = editorEl.scrollHeight` whenever `showAddControl` becomes true. Hiding the control again lets the editor expand back to full height on its own (no scroll-back needed).
- **Manual partition page consumes the full unallocated space (no end-of-disk guard)** — removed the 2 MB end-of-disk guard (`endOfDiskGuardMB`) from `frontend/src/pages/ManualPartitionPage.svelte`. "Use remaining" and the slider now consume the entire free space (`availableAddMB` now equals `unallocatedMB` / `computeFreeMB` in full), so the last 2 MB of a disk is no longer left untouched when a partition fills it. The manual partition page's clickable "Free" row and the add-new-partition control it reveals are otherwise unaffected.
- **Manual partition page: add-control revealed by clicking unallocated space** — the manual partition page (`frontend/src/pages/ManualPartitionPage.svelte`) now shows a clickable "Free" row at the bottom of the partition editor whenever the disk has unallocated space (`unallocatedMB`, derived from `computeFreeMB`). Clicking that row toggles the "Add new partition" control (`showAddControl` state): it appears on the first click and hides again on a second click. The row is keyboard-operable (`role="button"`, `tabindex="0"`, Enter/Space) and carries a CSS-only chevron indicator (`.unallocated-indicator`, rotates between open/closed) so no new Nerd Fonts glyph was needed. The add-control is wrapped in `{#if showAddControl}`, so it only renders once the unallocated row is active. Free size is shown in full (no end-of-disk guard); `availableAddMB` derives from the new `unallocatedMB`. Label reuses the existing `manual.free` string.
- **CLI installs btrfs by default** — the `--filesystem` flag default in `backend/cli/main.go` now reads `shared.DefaultFileSystem` (`"btrfs"`) instead of a hardcoded `"ext4"`, so `aelum-installer-cli --install <disk>` with no `--filesystem` flag installs btrfs. `--filesystem ext4` still overrides it. This matches the GUI, which already selects `DefaultFileSystem`.
- **Copies the branded `os-release` onto the installed system** — added a copyjob (`/etc/os-release` → `/mnt/etc/os-release`) to `ISOCopyJobs` in `backend/install/users/users.go`, so the Aelum-branded `airootfs/etc/os-release` from the live ISO overwrites the default `archlinux-release` file during the `setup_users` step. The live ISO's `os-release` now reports `NAME`/`PRETTY_NAME` = `Aelum` (kept `ID=arch`, `ID_LIKE=archlinux` so distro detection is unaffected) with Aelum-brand URLs and an `ANSI_COLOR` truecolor value matching the brand purple (`#9b7ff2`).
- **Theme toggle switches the live-ISO Hyprland wallpaper — toggling the header light/dark button now also swaps the running hyprpaper background to match. A new Wails binding `App.SetWallpaper(theme)` calls `hyprctl hyprpaper wallpaper ",<path>,cover"` directly (empty monitor target applies to all outputs), using the live-ISO-only backgrounds `bg-light.png` / `bg-dark.png` (`shared.LiveIsoBgLight` / `shared.LiveIsoBgDark` in `backend/shared/config.go`). The live ISO's `hyprpaper.conf` default was moved from `bg.png` to `bg-light.png`. The call is best-effort from the frontend (`ThemeToggle.svelte`): it runs as the session user and its rejection is swallowed so a missing `hyprctl` (e.g. dry-run on a host) can never break the toggle. The installed-system DMS wallpapers (`wallpaper-dark.jpg` / `wallpaper-light.jpg`, `WallpaperSourceDark`/`WallpaperSourceLight`) are unaffected.
- **Installer light/dark theme toggle** — a sun/moon button in the header (`frontend/src/components/ThemeToggle.svelte`, placed next to the dry-run badge) flips the whole wizard between a light and a dark (mauve/rose/tan on inverted dark surfaces) scheme. The active theme lives on `<html data-theme>` via CSS variable overrides in `frontend/src/style.css`, matching the website's `live-iso`/`website` theme tokens. The choice is persisted to `localStorage` under `aelum-theme` and falls back to the OS `prefers-color-scheme`; a no-flash inline script in `frontend/index.html` applies it before first paint. The toggle is localized (`app.themeToLight` / `app.themeToDark`; other locales fall back to English via the existing i18n fallback). Icons are inline SVGs rather than Nerd Fonts glyphs because the installer's self-hosted `NerdFontsSymbols.woff2` subset does not ship the website's sun/moon code points.
- **Theme toggle strings localized in all 28 locales** — the light/dark toggle's `app.themeToDark` / `app.themeToLight` strings (`frontend/src/translations/*.json`) are now translated in every locale instead of falling back to English. Added after `app.dryRun` (keeping alphabetical key order) in all 27 non-English files; all 28 locales verified to share an identical key set (162 keys).
- **nautilus-open-any-terminal context menu extension** — added `nautilus-open-any-terminal` (AUR) to the desktop packages list, which installs a Nautilus extension that adds a context-menu entry for opening the default terminal emulator in the current directory. The extension supports 30+ terminal emulators; the default is configured to `kitty` via a system-wide dconf setting (`/etc/dconf/db/local.d/02-nautilus-terminal`). The setting is baked into the live ISO's compiled dconf database and copied to the installed system during installation.
- **LUKS2 root encryption (GUI + CLI)** — the installer can now encrypt the root partition with LUKS2. On the Disk Selection page a new "LUKS" pill opens the `LuksPassphraseDialog.svelte` (confirm-twice passphrase entry); committing a valid passphrase flips `installState.luksEnabled` and shows the "Encrypted with LUKS2" note on the Confirmation page. The committed state is synced to the Go backend at the installation choke point (`InstallationPage.init()` → `SetLuks` / `SetLuksPassphrase`), which is what makes the CLI actually encrypt — without the sync the GUI showed LUKS enabled but spawned the CLI without `--luks` and installed an unencrypted root. The backend `App` holds the enabled flag and a zeroed passphrase buffer (`navigation.go`); `StartInstallation` appends `--luks` to the CLI args and feeds the passphrase to the child's stdin (after the account password, matching the CLI's sequential stdin reads), never logging it. The CLI already exposed a `--luks` flag that reads a second passphrase from stdin; both paths share `Installer`/`InstallContext` (`luks` + `luksPassphrase`, zeroed after copying to the context) and the `format` step's `EncryptRoot` path (LUKS2 header → mapper open → mkfs → btrfs subvolumes on the mapper → mapper close). Crypto parameters are pinned in `backend/shared/config.go` (luks2, `aes-xts-plain64`, 512-bit, `sha256`/`argon2id`, 2000 ms KDF time, matching cryptsetup 2.4+ and documented in `luks.md`). Cleanup closes the mapper on failure so installs are retryable. Strings localized in all 28 locales; covered by `frontend/src/lib/luks.store.test.ts`.

### Refactored
- **Disk/partition size fields are now `int64` instead of `string`** — `DiskInfo.Size`, `PartitionDetail.Size`, `PartitionEntry.Size`, and `DiskSelectionData.Size` are all `int64` (raw byte count). `FormatSize()` now takes `int64` directly. This eliminates repeated `fmt.Sscanf`/`strconv.ParseInt` calls scattered across consumers, removes a class of silent-garbage bugs from string parsing, and simplifies both backend and frontend code (`parseInt()` calls removed from `DiskCard.svelte`, `AppFooter.svelte`, and `navigation.ts`).
- **`DerivePartitionPath` uses last-character check instead of `/dev/nvme` prefix** — the old `strings.HasPrefix(diskID, "/dev/nvme")` was fragile. The new version checks whether the last character of the disk name is a digit: if so, inserts `p` (NVMe convention: `nvme0n1p1`); otherwise appends directly (`sda1`). Handles all device types uniformly.
- **Extracted `format.BuildPartitionInfo`** — a shared helper that reads UUIDs via `blkid` and builds a `PartitionInfo` with btrfs subvolume mount points. `partition.Apply()` now uses it instead of duplicating UUID reading + struct construction, and the now-unused `readUUID` was removed from `partition.go`.
- **`ManualLayout.FreeMB` no longer has a JSON tag** — it is derived, never serialized, so the tag was misleading.
- **Consolidated `PartitionDetail` into `PartitionEntry`** — the two structs served different purposes (internal discovery vs. frontend display) but overlapped heavily. `PartitionEntry` now carries `Name` and `Mountpoints`, serves both the backend (`format.Run`, `ComputeLayout`) and frontend (`GetDiskPartitions`). `SizeFormatted` moved to the frontend where `FormatSize()` computes it from `Size`. Removed unused `Trans` field from `PartitionEntry`.

### Fixed
- **Welcome page RTL (Arabic/Persian) language rows no longer wrap to two lines** — the language list used `font-family: inherit`, so the Arabic glyphs fell back per-glyph through fontconfig. On the ISO that fallback selected a taller Noto variant (Naskh/Nastaliq) than the dev host did, making the selected language row balloon to ~2 lines while the Latin/CJK/Hebrew rows stayed normal. The font files are byte-identical across host and ISO, so this was not a missing font, a metrics difference, or a stale build — it was fontconfig's script→font selection differing between environments. Fixed by pinning the compact font on `.lang-item` (`font-family: "Noto Sans Arabic", "Noto Sans", "Nunito", sans-serif;`) with an explicit `line-height`/`min-height`, so the row height no longer depends on which variant the fallback happens to pick. Noto variants share one Latin core, so the parenthetical country names render identically to before; the fix also covers Persian, which shares the Arabic script block.
- **Arabic/Hebrew script renders at normal height across every installer page, not just the welcome list** — the welcome fix pinned the compact font on one element, but the base `--font-family` stack still had no Arabic/Hebrew script fonts, so any other RTL element (form fields, labels, cards, tags — anything using `font-family: inherit`, `var(--font-family)`, or the undefined `--font-sans`) still fell back per-glyph through fontconfig to a taller Naskh/Nastaliq variant and rendered ~2x taller than Latin. Fixed by adding `"Noto Sans Arabic"` and `"Noto Sans Hebrew"` to the base stack in `frontend/src/style.css`, so RTL glyphs resolve per-glyph to the compact Noto variants everywhere at once. This is the same pin as the welcome fix, applied app-wide at the root instead of per-page; the welcome page keeps its flex/`min-height` row tuning. Noto's shared Latin core means country names and other scripts render identically, so Hebrew (its own script block) is covered too.
- **Manual partitioning no longer creates a brand-new root below its minimum size when free space is fragmented** — `buildActions` clamps a brand-new explicit partition to the largest contiguous free gap (to avoid an `sgdisk` "extends past the last usable sector" error), but `Validate` checks the *requested* size against the role floor (ESP ≥ 128 MiB, System ≥ 8 GiB) using only total free space, which cannot see fragmentation. On a disk where a kept partition splits the free space into two gaps each smaller than 8 GiB (yet together larger than 8 GiB), an 8 GiB root could be silently carved down to a ~6 GiB gap and still pass validation, producing an unusably small root that fails later at package install. Fixed by having `buildActions` re-check the *resolved* (clamped) size against the floor and return a clear error when the largest contiguous gap is too small; a "use all remaining space" row stays exempt (its floor is the disk). Added a `minPartitionSizeMB` helper mirroring `Validate`'s floors, plus `TestBuildActions_ClampedRootBelowMinimumErrors` and `TestBuildActions_ClampedRootFitsNoError`.
- **Manual mode can now add a partition when the last existing partition reaches the end of the disk** — `partition.buildActions` used to carve every brand-new partition *after* the last existing one (at the disk end). On a disk where the final partition already sits at the very end but an earlier deleted partition had freed space at the front, this appended the new partition past the disk and `sgdisk` rejected it (`Could not create partition N from <near-end> to <past-the-end>`), even though the freed space fit. New partitions are now placed in the first free gap that fits (or the largest gap for "use all remaining space"), so freed front/back space is usable instead of only space at the end. Partition numbers stay the next-available GPT index (which the kernel exposes as `/dev/<disk>N` regardless of position), so device paths still resolve. Covered by `TestBuildActions_NewPartitionFillsEarlyGap`.
- **Manual-mode "new partition sizes exceed the free space" error no longer fires on a valid plan** — the frontend Disk Selection gate (`getManualLayoutValidationReasons`) measured headroom with `computeFreeMB`, which already subtracts the brand-new rows, then compared those same new rows against the reduced value. Any plan whose new partitions made up a large share of the disk was wrongly rejected (`new partition sizes (X MB) exceed the free space (Y MB)`), which is why it seemed to appear only when several partitions (e.g. 2 ESP) were added. Fixed by computing headroom as disk minus existing (on-disk) partitions only and comparing the new partitions against that; brand-new rows are no longer double-counted. The backend `Validate` already did this correctly (it skips new rows), so the two now agree. Covered by `frontend/src/lib/store.test.ts`.
- **Cannot get stuck on the disk selection "select a disk first" hint after leaving manual mode** — entering manual mode with a disk, then deselecting the disk (or navigating back to the user page and forward again) left `manualMode` set with no disk selected, so the page showed the dead-end "select a disk, then switch to manual mode…" message with no way to continue. Added a self-healing effect on the Disk Selection page that falls back to automatic mode whenever manual mode is on but no disk is selected, and `deselectDisk` now also clears manual mode. Manual partitioning is only reachable with a disk selected, so a diskless manual state is always stale.
- **Manual-mode "select a disk first" tooltip no longer gets clipped at the page edge** — the tooltip is absolutely positioned (`right: 0`) relative to the mode pills, which sit at the far right of the top bar, so its edge landed exactly on `.page-content`'s `overflow: hidden` clip and got sliced. Removed `overflow: hidden` from `.page-content` (it was unnecessary; the column is sized via `flex`/`min-height: 0` and its own inner scrollables handle overflow).
- **All 28 localization files now have complete translations** — added 44 missing keys (manual partition mode, filesystem/disk labels) to all 27 non-English locales and fixed several incorrect translations (Bulgarian "vomit" → "changed", Arabic/Polish/Indonesian/Persian "freedom" → "free space", Finnish "of" was a slash character, Esperanto "manuals" → "manual")
- **Manual-mode confirmation partition table no longer overflows the right page column and now renders a clean rounded border** — the plan was laid out with a flex row of grid cells using `fr` columns stretched to `width: 100%`, which pushed the table wider than `page-content` (clipped by its `overflow: hidden`) and left an empty gap in the FS column. Rewrote it as a native `<table>` (`<thead>`/`<tbody>`, `border-spacing: 0`) so every column aligns automatically; the SIZE column is right-aligned so numbers line up under the header. Removed `overflow: hidden` and `border-collapse` from the table (replaced with `border-spacing: 0`), which were clipping the rounded border at the corners. Added the new table-column labels (`NAME`/`SIZE`/`ROLE`) and shortened the FS label to `FS` in `en-US.json`.
- **Manual-mode confirmation partition table scrolls internally (not the page) and stays vertically centered** — a long plan (10+ partitions) is taller than the right column. A first attempt filled the column with a flex chain so the table scrolled, but that stretched the summary and lost the vertical centering; forcing `page-content` to scroll scrolled the whole page instead of just the table. The summary is now naturally sized and centered via `justify-content: center` on `.page-content`, and `.plan-scroll` is bound by JS (`updatePlanScrollHeight`) to the space left after the fixed summary content (language, user, disk header). When the table fits, the summary stays centered; when it doesn't, the table grows to fill the column and scrolls internally. `.plan-scroll` uses `overflow: auto` (vertical for tall plans, horizontal on narrow windows via the table's `min-width: max-content`), and `.page-content` stays `overflow: hidden` so the page never scrolls. Re-measures on partition add/remove and window resize.
- **Confirmation dialog no longer fails to re-open after pressing Cancel or Confirm** — the shared `ConfirmDialog` drives its visibility from a `show` prop created with `$bindable(installState.showConfirmDialog)`, but `App.svelte` rendered `<ConfirmDialog />` with no `bind:`. In Svelte 5 a `$bindable()` default only syncs once when the parent doesn't bind, so the dialog opened the first time the flag was set, but once the child wrote `show = false` back on Cancel/Confirm the link detached and later flag sets were ignored. Fixed by binding in both callers: `App.svelte` now uses `bind:show={installState.showConfirmDialog}` for the install confirmation, and `ManualPartitionPage` uses `bind:show={showDeleteDialog}` for the delete dialog (its old one-way `show={showDeleteDialog}` never reset the flag on dismiss, so a second delete wouldn't re-open it).
- **Manual partitioning no longer rejects a fully-partitioned disk where free space is smaller than the GPT backup region** — `Validate`'s strict new-partition guard (`newSectors > freeSectors - gptBackupSectors`) fired even when there were zero new partitions (`newSectors == 0`), because existing rows can leave fewer free sectors than the trailing GPT backup area. Added a `newSectors > 0` guard so the check only applies when brand-new partitions are actually being added.
- **Manual partitioning slider no longer snaps to the middle after deleting a partition** — deleting a row makes the available space jump, which moves the size range's `max`; a bound range left with a shifted `max` can stay stuck at its browser-computed midpoint, and because `addSizeMB` didn't itself change value Svelte's `bind:value` never re-wrote the DOM to unstick it. Added an effect that re-asserts a valid value on the slider whenever available space changes (clamped to the slider's own `max`, so a large typed value isn't pulled back down). This never fires an input event, so it doesn't fight user drags or the shared binding. Removed the temporary `[MANSLIDER]` debug logging that had been added to shadow the issue.
- **Manual partitioning rejects an ESP below 128 MiB or a system partition below 8 GiB** — the manual editor let the user designate any size, so a 1 MiB row could be assigned System (or a tiny ESP created) and pass the UI, then only fail later at install. Added an enforced floor matching the automatic installer: `shared.MinESPSizeBytes` (128 MiB) and `shared.MinSystemPartitionBytes` (8 GiB, the disk floor). `Validate` rejects a designated ESP/System row whose size is below the floor, computed byte-exactly for existing rows (MiB fallback for brand-new ones). A "use all remaining space" row (sizeMB 0) is exempt — its size is whatever the disk leaves. The frontend mirrors this in a new `isManualLayoutValid` used by the Disk Selection page gate, so "Next" stays disabled until the designated partitions meet the floor. The new constants are auto-emitted to `frontend/src/lib/constants.ts` and covered by `TestValidate_MinPartitionSizes` and `frontend/src/lib/store.test.ts`.
- **Manual partitioning no longer rejects a brand-new partition that replaces a deleted one** — `Validate`'s strict, sector-free-space check read `layout.FreeSectors`, which `ComputeLayout` stamps at disk-load time and is never updated after the user edits the plan. Deleting an existing row and adding a brand-new one in its place frees real room, but the stale free-space value still reflected the original layout, so a valid plan (the frontend recomputes free space correctly and enables "Next") was hard-rejected by the backend (`new partition sizes exceed the free space`). Fixed by recomputing free space in `Validate` from the live partition list: existing rows are counted by exact byte size (MiB fallback), brand-new rows are skipped since `newSectors` already accounts for them, and deleted rows are naturally excluded (they live on `DeletedPartitions`, not `Partitions`). The coarse MiB-sum guard and the genuine-overflow rejection are unchanged. Added `TestValidate_NewPartitionFreesSpaceFromDeletedRow`.
- **Manual partitioning no longer over-allocates a brand-new partition's size from truncated MB** — the free-space allowance counted existing partitions rounded *down* to MiB, but the partitions occupy their exact raw sectors, so free space was overstated by roughly the summed truncation remainders (~1 MiB per existing partition). On a Windows dualboot (4–6 kept partitions) an explicit new partition could pass the UI limit and `Validate` (both compare truncated MB against truncated disk size) yet then fail at `createPartition` with `partition extends past the last usable sector of the disk`. Fixed by carrying byte-exact geometry end-to-end: `shared.ManualLayout` gains `DiskSizeBytes` and `FreeSectors`, and each existing `shared.ManualPartition` now carries `SizeBytes`. `Validate` checks brand-new explicit partitions against free space *in sectors* (keeping the coarse MiB sum as a fallback), and `buildActions` measures free space in sectors too, clamping an explicit new-partition size to the true usable end instead of the requested value. `ComputeLayout` populates the new fields. The frontend `computeFreeMB` is now derived from byte-exact totals (`diskSizeBytes − Σ usedBytes`) so the UI allowance matches the backend. Added `TestValidate_NewPartitionRespectsFreeSectors` and `TestBuildActions_ClampsExplicitNewPartition`.
- **Manual partitioning no longer forces a 1 MiB partition when less than 1 MiB is free** — `buildActions` clamped an empty/free result to `available = 2048` sectors, carving a 1 MiB partition into a gap too small for it, which `sgdisk` rejected as extending past the last usable sector. Now clamps to 0 instead (an empty result), so a genuinely full disk yields nothing rather than an out-of-range partition. Covered by `TestBuildActions_ClampsExplicitNewPartition`.
- **Manual partitioning rejects a brand-new partition added after a "use all remaining space" one** — `Validate` only counted how many `sizeMB == 0` rows existed, not their order, so a "use remaining" row followed by another new partition would consume the disk then leave the second orphaned. Now `Validate` tracks whether a brand-new use-all row has appeared and rejects any further brand-new partition after it. The frontend already prevented this (adds are appended last and clear `availableAddMB`); this is the backend backstop. Added `TestValidate_UseAllOrdering`.

### Changed
- **Manual-partition "Add" control defaults to 1 MB instead of 0** — after adding a partition the size field/slider reset to 0, a blank value the user had to re-enter. They now reset back to the 1 MB default (matching the field's initial state), so the next partition starts from the same baseline.
- **Page-info headings/subtitles no longer carry default margin** — the wizard column headings (`<h2>`) and subtitles (`<p>`) across Welcome, User Account, Confirmation, and Disk Selection (automatic mode) now use shared `.page-info-title` / `.page-info-subtitle` reset classes (`margin: 0`) instead of relying on heading defaults.
